# 10. Delete — 해당 id 빼고 새 배열

> MECE: **B4 Delete** — 마지막 단계. 끝나면 원본 완성본과 같은 앱이 된다.

## 🎯 이 단계가 끝나면

**화면**
```
css 클릭      → 아래 메뉴: • Create  • Update  [Delete]
Delete 클릭   → 목록에서 css가 사라지고, Welcome 화면으로 돌아감
                 1. html
                 2. javascript
```

**꽂을 한 문장**: **삭제도 결국 새 배열 만들기.** C·U·D 모두 같은 공식 — **복사(또는 새로 만들기) → 바꾸기 → set**.

- 🟢 **초딩용**: 반 명단에서 한 명을 지울 때, 원본 명단에 줄을 긋지 않는다. 그 친구만 빼고 **새 명단을 다시 쓴다**. 선생님(React)은 새 명단을 보고 "바뀌었네" 하고 칠판을 고친다.
- 🔵 **개발자용**: `filter` 패턴. 조건(`id !== 삭제할id`)을 통과한 원소만 새 배열에 담아 set한다. 삭제 후에는 현재 `id`가 가리키는 글이 없으니 mode를 `WELCOME`으로 바꾼다.

## 📥 시작 코드 (= 09 정답 + TODO)

```js
import './App.css';
import {useState} from 'react';

function Header(props){
  return <header>
    <h1><a href="/" onClick={(event)=>{
      event.preventDefault();
      props.onChangeMode();
    }}>{props.title}</a></h1>
  </header>
}
function Nav(props){
  const lis = []
  for(let i=0; i<props.topics.length; i++){
    let t = props.topics[i];
    lis.push(<li key={t.id}>
      <a id={t.id} href={'/read/'+t.id} onClick={event=>{
        event.preventDefault();
        props.onChangeMode(Number(event.target.id));
      }}>{t.title}</a>
    </li>)
  }
  return <nav>
    <ol>
      {lis}
    </ol>
  </nav>
}
function Article(props){
  return <article>
    <h2>{props.title}</h2>
    {props.body}
  </article>
}
function Create(props){
  return <article>
    <h2>Create</h2>
    <form onSubmit={event=>{
      event.preventDefault();
      const title = event.target.title.value;
      const body = event.target.body.value;
      props.onCreate(title, body);
    }}>
      <p><input type="text" name="title" placeholder="title"/></p>
      <p><textarea name="body" placeholder="body"></textarea></p>
      <p><input type="submit" value="Create"></input></p>
    </form>
  </article>
}
function Update(props){
  const [title, setTitle] = useState(props.title);
  const [body, setBody] = useState(props.body);
  return <article>
    <h2>Update</h2>
    <form onSubmit={event=>{
      event.preventDefault();
      const title = event.target.title.value;
      const body = event.target.body.value;
      props.onUpdate(title, body);
    }}>
      <p><input type="text" name="title" placeholder="title" value={title} onChange={event=>{
        setTitle(event.target.value);
      }}/></p>
      <p><textarea name="body" placeholder="body" value={body} onChange={event=>{
        setBody(event.target.value);
      }}></textarea></p>
      <p><input type="submit" value="Update"></input></p>
    </form>
  </article>
}
function App() {
  const [mode, setMode] = useState('WELCOME');
  const [id, setId] = useState(null);
  const [nextId, setNextId] = useState(4);
  const [topics, setTopics] = useState([
    {id:1, title:'html', body:'html is ...'},
    {id:2, title:'css', body:'css is ...'},
    {id:3, title:'javascript', body:'javascript is ...'}
  ]);
  let content = null;
  let contextControl = null;
  if(mode === 'WELCOME'){
    content = <Article title="Welcome" body="Hello, WEB"></Article>
  } else if(mode === 'READ'){
    let title, body = null;
    for(let i=0; i<topics.length; i++){
      if(topics[i].id === id){
        title = topics[i].title;
        body = topics[i].body;
      }
    }
    content = <Article title={title} body={body}></Article>
    contextControl = <>
      <li><a href={'/update/'+id} onClick={event=>{
        event.preventDefault();
        setMode('UPDATE');
      }}>Update</a></li>
      {/* TODO 1: Delete 버튼 추가
            <li><input type="button" value="Delete" onClick={()=>{ ... }} /></li>
          TODO 2: onClick 안에서
            - 빈 배열 newTopics
            - for 문으로 topics 중 id가 "다른" 것만 push
            - setTopics(newTopics) → setMode('WELCOME') */}
    </>
  } else if(mode === 'CREATE'){
    content = <Create onCreate={(_title, _body)=>{
      const newTopic = {id:nextId, title:_title, body:_body}
      const newTopics = [...topics]
      newTopics.push(newTopic);
      setTopics(newTopics);
      setMode('READ');
      setId(nextId);
      setNextId(nextId+1);
    }}></Create>
  } else if(mode === 'UPDATE'){
    let title, body = null;
    for(let i=0; i<topics.length; i++){
      if(topics[i].id === id){
        title = topics[i].title;
        body = topics[i].body;
      }
    }
    content = <Update title={title} body={body} onUpdate={(title, body)=>{
      console.log(title, body);
      const newTopics = [...topics]
      const updatedTopic = {id:id, title:title, body:body}
      for(let i=0; i<newTopics.length; i++){
        if(newTopics[i].id === id){
          newTopics[i] = updatedTopic;
          break;
        }
      }
      setTopics(newTopics);
      setMode('READ');
    }}></Update>
  }
  return (
    <div>
      <Header title="WEB" onChangeMode={()=>{
        setMode('WELCOME');
      }}></Header>
      <Nav topics={topics} onChangeMode={(_id)=>{
        setMode('READ');
        setId(_id);
      }}></Nav>
      {content}
      <ul>
        <li><a href="/create" onClick={event=>{
          event.preventDefault();
          setMode('CREATE');
        }}>Create</a></li>
        {contextControl}
      </ul>
    </div>
  );
}

export default App;
```

## ✍️ 할 일

1. `contextControl`의 Update `<li>` 옆에 Delete 버튼 `<li>`를 추가한다. (08번에서 `<></>`로 감싸 둔 이유가 여기서 드러난다)
2. onClick에서 id가 **다른** 글만 새 배열에 담고, `setTopics`한 뒤 `WELCOME`으로 보낸다.
3. css를 삭제해 보고 목록에서 사라지는지 확인한다.
4. **실험**: `setMode('WELCOME')`을 빼고 삭제해 본다 → 본문 제목과 내용이 비는 걸 확인한다. 왜 그런지 말로 설명한 뒤 되돌린다.
5. **종합 시나리오**: Create(4번 추가) → Update(4번 수정) → Delete(4번 삭제) → 다시 Create → 새 글 번호가 **5번**인지 확인한다. 4번이 아닌 이유도 설명해 본다.

<details>
<summary>💡 힌트 1 — 왜 &lt;a&gt;가 아니라 &lt;input type="button"&gt;?</summary>

Create와 Update는 "그 화면으로 **이동**"이라 링크(a)를 썼다. Delete는 이동할 곳 없이 누르는 즉시 **실행**되는 동작이라 버튼을 쓴다. 그래서 `preventDefault`도 필요 없다 (버튼에는 막을 기본 동작이 없다).
</details>

<details>
<summary>답 보기</summary>

1. **원본을 고치지 않고 새 배열을 만들어 set한다.** Create는 복사 후 추가, Update는 복사 후 교체, Delete는 걸러서 새로 만들기.
2. mode는 READ인데, `id`가 가리키는 글이 `topics`에서 사라졌다. for 문이 아무것도 못 찾아서 title과 body가 비어 있는 채로 Article이 그려진다.
3. `nextId`는 삭제해도 줄어들지 않는다. 의도된 동작이다. 지운 번호를 다시 쓰면, 옛 글을 가리키던 링크나 기록이 엉뚱한 새 글을 가리키게 된다. 실무 DB의 auto increment도 같은 이유로 번호를 재사용하지 않는다.
</details>
