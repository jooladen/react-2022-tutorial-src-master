## 🎯 이 단계가 끝나면

**화면**
```
WEB
 1. html
 2. css
 3. javascript
 4. react            ← 새로 추가한 글
react
react is ...         ← 추가 직후 바로 그 글이 보임
 • Create            ← 화면 아래 링크
```
Create 클릭 → 입력 폼 → title "react", body "react is ..." 입력 → Create 버튼 → 목록에 4번 추가 + 본문에 표시

**꽂을 한 문장**: **원본 배열을 고치면 화면이 안 바뀐다.** 복사해서 새 배열을 만들고, 그 새 배열을 set 함수에 넘긴다 (불변성).

- 🟢 **초딩용**: 선생님(React)은 공책을 **표지만 보고** 바뀌었는지 판단한다. 같은 공책 안에 한 줄 더 써서 내면 "아까 그 공책이네" 하고 안 읽는다. **새 공책에 옮겨 적어서** 내야 "새 거네" 하고 읽는다.
- 🔵 **개발자용**: React는 state 변경을 `Object.is(이전값, 새값)`, 즉 참조 비교로 판단한다. `topics.push()` 후 `setTopics(topics)`를 하면 같은 참조라서 렌더링이 생략된다. `[...topics]`로 새 참조를 만들어야 한다. 원시값(문자열, 숫자)은 값 자체가 바뀌므로 상관없다.

import './App.css';
import {useState} from 'react';

function Header(props){
  return <header>
    <h1><a href="/" onClick={(event)=>{
      event.preventDefault();
      props.onChangeMode();
    }}>{props.title}</a></h1>
  </header>
}
function Nav(props){
  const lis = []
  for(let i=0; i<props.topics.length; i++){
    let t = props.topics[i];
    lis.push(<li key={t.id}>
      <a id={t.id} href={'/read/'+t.id} onClick={event=>{
        event.preventDefault();
        props.onChangeMode(Number(event.target.id));
      }}>{t.title}</a>
    </li>)
  }
  return <nav>
    <ol>
      {lis}
    </ol>
  </nav>
}
function Article(props){
  return <article>
    <h2>{props.title}</h2>
    {props.body}
  </article>
}

//                      → props.onCreate(title, body) 호출

function App() {
  const [mode, setMode] = useState('WELCOME');
  const [id, setId] = useState(null);
  // TODO 2: nextId state 만들기 (초기값 4)
  // TODO 3: 아래 topics를 state로 바꾸기
  const topics = [
    {id:1, title:'html', body:'html is ...'},

  } else if(mode === 'READ'){

## 🔧 실무 버전

- 복사와 추가를 한 줄로: `setTopics([...topics, newTopic]);`
- set 함수에 함수를 넘기는 방식(`setNextId(prev => prev + 1)`)이 연속 호출에 안전하다. 강의 수준에서는 위 방식으로 충분하다.
- 실무 id는 서버나 DB가 만든다. nextId 수동 관리는 학습용이다.

<details>
<summary>답 보기</summary>

1. React는 이전 값과 새 값이 같은 참조인지만 본다. 같은 배열을 넘기면 "안 바뀌었다"고 판단해 다시 그리지 않는다.
2. setter로 다른 state를 바꿀 때마다 App이 다시 실행되고, 그때마다 `nextId`는 다시 4가 된다. 그래서 새 글이 모두 id 4가 되어 겹친다.
3. 문자열·숫자는 값 자체가 새 값이라 비교하면 바로 다르다. 배열·객체는 내용물만 바뀌고 참조(주소)는 그대로라서, 새 참조를 만들어 줘야 한다.
4. "어떤 글"을 수정할지 정해져 있을 때, 즉 READ 화면에서만 보여야 한다. Welcome 화면에는 수정할 대상이 없다.
</details>
